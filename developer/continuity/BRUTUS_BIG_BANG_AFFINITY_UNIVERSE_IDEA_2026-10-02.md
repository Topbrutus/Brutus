## 1. CORE IDEA

Brutus begins inside a bounded **Genesis zone**.

The Genesis zone contains the real runtime elements that actually exist:

- Fourmis;
- crystals;
- dust;
- machines;
- wheels / mechanisms;
- traces;
- local structures.

The zone is fenced so nothing can spread farther than the admitted runtime scope.

The visual universe must remain a read-only representation of the real Brutus state.

```text
BRUTUS RUNTIME = SOURCE OF TRUTH
VISUAL UNIVERSE = READ-ONLY MIRROR
```

No visual filler or simulated population is allowed in the production path.

## 3. MAGIC 7 EXPANSION SPACE

TopBrutus wants the expansion keyed around powers of seven.

Important exact values:

```text
7^3 = 343
7^4 = 2401
7^7 = 823543
```

Possible interpretation:

- 343 = 7×7×7 physical/logical cube cells;
- 2401 = 343 × 7 phase/state slots;
- 823543 = very large address space / dispersal lattice for a Big Bang event.

The system does not need to instantiate 823543 physical cubes.

It may use `7^7 = 823543` as a deterministic address space for expansion and placement.

## 4. BIG BANG IS A SCALE TRANSFORMATION

The Big Bang must not be implemented as destructive physical chaos.

It is primarily:

```text
LOCAL POSITION
    ↓
DETERMINISTIC SCALE / WORLD MAPPING
    ↓
UNIVERSE POSITION
```

Objects keep:

- their stable identity;
- their lineage;
- their pedigree;
- their traces;
- their parent references;
- their runtime history.

Required invariant:

```text
BIG_BANG != RESET
BIG_BANG != PEDIGREE LOSS
BIG_BANG != IDENTITY LOSS
BIG_BANG != RANDOM FABRICATION
```

## 5. FOURMIS DURING THE EXPANSION

TopBrutus does NOT want to duplicate the same Fourmi merely to increase population.

Instead, a real population may be gathered in Genesis and redistributed through known worlds.

Example concept:

```text
1000 REAL FOURMIS
       ↓
BIG BANG / EXPANSION
       ↓
WORLD A
WORLD B
WORLD C
...
       ↓
each Fourmi resumes local activity
```

Each Fourmi preserves:

```text
ANT_ID
MEMORY
LINEAGE
PEDIGREE
TRACE HISTORY
```

Only its world / position changes.

If future reproduction is implemented, descendants must receive new ANT_ID values and explicit parentage.

```text
MIGRATION != CLONING
CHILD != PARENT
```

## 6. CRYSTAL AFFINITY / PSEUDO-GRAVITY

TopBrutus proposed a very weak attraction system.

The preferred interpretation is an **affinity field**, not a heavy Newtonian physics engine.

Candidate crystal state:

```text
CRYSTAL_ID
POSITION
POLARITY
MASS
AFFINITY
CLUSTER_ID
LINEAGE
PEDIGREE
LATEST_TRACE
TICK
```

Possible polarity values:

```text
-1
+1
```

Exact semantics are not frozen yet.

Conceptual behavior:

- isolated dust/crystals attract only very weakly;
- nearby compatible pieces drift together slowly;
- several nearby pieces can form a spatial cluster;
- a larger cluster gains a slightly larger local influence;
- attraction remains bounded and local;
- distant objects do not interact directly.

The visual goal is to let structures emerge gradually:

```text
DUST
 -> GRAINS
 -> SMALL CLUSTERS
 -> CRYSTALS
 -> CLUSTERS
 -> BALLS / NODES
 -> ACTIVITY ZONES
```

## 7. FOURMI ATTRACTION TO CLUSTERS

Fourmis may also react to local crystal concentrations.

Do not make every Fourmi automatically fall into the largest cluster.

Instead use a bounded local sensitivity, for example:

```text
ANT_AFFINITY_TO_CRYSTAL
```

A nearby cluster may slightly bias a Fourmi trajectory.

Possible behaviors later:

- inspect cluster;
- collect material;
- transport crystal;
- deposit material;
- leave trace;
- move away;
- continue mission.

This keeps local autonomy and avoids a single global attractor swallowing the whole system.

## 8. DUST DISTRIBUTION

Brutus may continuously produce dust.

That dust can be injected across the admitted internal universe.

Desired behavior:

```text
BRUTUS PRODUCES DUST
        ↓
DETERMINISTIC PSEUDO-RANDOM DISTRIBUTION
        ↓
WORLDS / CORRIDORS / BUBBLES
        ↓
LOCAL WEAK AFFINITY
        ↓
ACCUMULATION
        ↓
EMERGENT STRUCTURES
```

Use a deterministic seed / event identity so the same input state can reproduce the same distribution.

```text
PSEUDO-RANDOM != UNTRACEABLE RANDOM
```

Every distribution event should remain reproducible and traceable.

## 9. CPU / PERFORMANCE RULE

Never perform all-pairs attraction.

Forbidden design:

```text
EVERY CRYSTAL × EVERY OTHER CRYSTAL
```

Use spatial partitioning.

Example conceptual grid:

```text
WORLD
┌───┬───┬───┐
│ A │ B │ C │
├───┼───┼───┤
│ D │ E │ F │
├───┼───┼───┤
│ G │ H │ I │
└───┴───┴───┘
```

Each object only evaluates:

- its own cell;
- bounded neighboring cells.

Static objects should cost almost nothing.

Only changing / moving entities should enter active update work.

Global design principle:

```text
1 AUTHORITATIVE CLOCK
 -> EVENT / DELTA
 -> LOCAL SPATIAL UPDATE
 -> VISUAL INTERPOLATION
```

The larger Brutus universe is intended to include:

```text
9 CORRIDORS
+ BUBBLES
+ MULTIPLE WORLDS
```

Genesis begins fenced.

Expansion is gradual.

Before the Big Bang:

```text
everything concentrated in Genesis
```

At Big Bang:

```text
real objects receive admitted universal destinations
```

After Big Bang:

```text
objects become spatially sparse
then slowly reconcentrate through local affinity
```

This gives the universe a useful symmetry:

```text
GENESIS
very concentrated
        ↓
BIG BANG
very dispersed
        ↓
WEAK AFFINITY
        ↓
local concentrations
        ↓
clusters / balls / worlds
```
